## 트러블슈팅 · 설계 판단

### 🧭 Navigation

#### 1. 다른 화면에 다녀오면 선택한 날짜가 오늘로 리셋됨
- **원인**: 복귀 시 컴포지션이 재생성되며 `LaunchedEffect`가 다시 돌아 오늘 기준으로 재로딩
- **해결**: "단순 재진입"과 "작성 완료"를 구분. 재진입은 로딩 skip, 작성 완료만 `savedStateHandle` 결과 신호로 새로고침
- **교훈**: "언제 새로고침해야 하는가"를 이벤트로 정의하면 불필요한 갱신과 상태 유실을 같이 막는다

#### 2. 화면 간에는 객체가 아니라 ID만 넘긴다
수정 화면에 `recordId`만 넘기고 화면이 재조회한다. 원시 타입 인자가 안전하고, 항상 최신 데이터를 보장하며, 화면 간 결합을 줄인다. 작성/수정은 이 ID의 유무로 모드를 나누는 단일 화면(AddEdit 패턴)으로 통합.

### 🏗 설계

#### 3. 권한은 UI와 데이터 양쪽에서
UI는 본인 기록에만 수정 버튼을 노출(편의), 데이터는 서버 단에서 재검증(실제 방어). 인원 제한처럼 불변식이 걸린 작업은 트랜잭션으로 최종 방어.

#### 4. 비즈니스 규칙은 Domain `Policy`에, 검증은 성격에 맞는 레이어에
"최대 4명", "최대 1440분"은 `GroupPolicy` / `WorkoutPolicy`에 단일 정의. 동시성 불변식인 인원 제한은 트랜잭션에서, 단순 입력 제한인 시간 상한은 입력 단계에서 검증.

#### 5. 기기 I/O는 도메인 밖으로
갤러리 저장 · 외부 링크 · 이미지 선택은 비즈니스 로직이 아니라 플랫폼 기능이라 UseCase를 거치지 않는다. `Content`는 콜백만 받아 순수성 유지.

### 🖼 이미지

#### 6. 이미지 수정 3상태를 필드 하나로
`https://`(유지) / `content://`(교체) / `null`(제거)를 `imageUri` 형태로 구분해 플래그를 늘리지 않음. 교체는 **업로드 먼저, 삭제 나중** — 반대면 업로드 실패 시 인증샷이 깨지고, 이 순서의 최악은 고아 파일 하나다.

#### 7. 압축을 넣자 세로 사진이 누웠다
- **원인**: 재인코딩 시 EXIF Orientation 유실. 추가로 `putBytes`는 contentType을 추론하지 않아 `octet-stream`으로 올라감
- **해결**: `ExifInterface`로 각도를 읽어 **픽셀 자체를 회전**, `storageMetadata`로 `image/jpeg` 명시
- **결과**: 평균 **6MB → 400KB (약 93% 감소)**, HEIC가 JPEG로 바뀌며 Android 9 미만 미표시 문제도 해소

#### 8. 추출 이미지 텍스트 오버플로우
캡처 결과물이라 넘치면 그대로 깨진다. 운동 시간/종목을 우선 보존하고 닉네임/소감이 말줄임으로 양보. 4자리부터 깨지는 시간 입력은 정책(1440)으로 입력 자체를 제한. 투명 영역이 없어 포맷은 JPEG.

### 🔒 보안 규칙

#### 9. `write`에는 `delete`가 포함된다
`allow write: if ... && contentType.matches('image/.*')`로 걸었더니 삭제 요청엔 `request.resource`가 없어 **기록 삭제 · 사진 교체 · 나가기 · 탈퇴가 전부 막힘** → create/update와 delete를 분리.

#### 10. 규칙은 배포된 모든 버전에 즉시 적용된다
압축이 없는 구버전 사용자가 남아 있는데 5MB 제한을 걸면 그들의 업로드가 즉시 실패한다. 타입 제한은 즉시, 크기 제한은 신버전 보급 후로 나눠 적용.

### 📦 출시

#### 11. applicationId 변경
`com.example`은 Play가 거부 → 출시 후 변경 불가라 출시 전에 패키지 · namespace · Firebase 앱 등록 · SHA-1 · `google-services.json`까지 일괄 변경. 리네임 후 Hilt가 옛 generated 클래스를 참조하는 오류는 `clean`으로 해결.

## 기능

- **그룹 통계** — 기록 / 통계 탭 분리, 주간 요일별 차트, 월간 집계, 그룹원 비교. 여러 그룹에 같은 운동을 올릴 수 있어 **통계는 그룹 범위로 한정**

- **홈 화면 위젯 3종** (Glance) — 오늘 기록 / 그룹 현황 / 이번 주. 런처가 이미 선택지를 보여주므로 앱 안에 위젯 설정 화면은 만들지 않음
- **UI 전면 개편**
    - M3 라이트/다크 색 스킴 직접 정의, 타이포 15개 슬롯 · Shape 정의, 위젯까지 동일 테마
    - Pretendard 3웨이트 (Medium은 한글 본문에서 Regular와 구분되지 않아 제외, 약 1.5MB 절감)
    - 홈에 `●●○○ 오늘 1/4` · 미작성 배지 추가 — **색과 폰트로는 고칠 수 없던 정보 부족 문제**
    - 그룹 상세에서 카드 제거 (사진이 주인공), 흩어져 있던 이미지 비율(16:9 / 1:1 / 4:3) 통일
- 사진 추출 결과물의 글꼴 배율을 1로 고정 (기기 설정과 무관하게 같은 이미지)
- 캘린더에 본인이 기록한 날 표시 — `DatePicker`에 날짜별 표시 슬롯이 없어 월 캘린더를 직접 그림 (주 시작은 통계와 맞춰 월요일)
- API 키를 패키지명 + SHA-1로 제한, 보안 규칙 · 인덱스를 레포로 편입

## 트러블슈팅 · 설계 판단

### 🔔 알림

#### 1. 앱 안에 알림 on/off를 만들지 않음
채널이 하나뿐이라 **OS가 이미 채널별 스위치를 제공**한다. 복사판은 DataStore · Firestore · OS 상태를 맞추는 비용만 만든다. 영구 차단된 사용자를 위한 **저장하지 않는 상태 표시 한 줄**만 남김.

#### 2. 스케줄 발송의 함정 세 가지
- **서버는 UTC** → KST 자정 경계를 직접 계산
- **재시도 끔** (`retryCount: 0`) → 한 번 놓치는 것보다 중복 발송이 더 나쁘다
- **죽은 토큰은 발송 실패 코드로만 정리된다** → 앱 삭제는 로그아웃을 거치지 않음

#### 3. 로그아웃 시 토큰은 `signOut()`보다 먼저 지운다
토큰은 계정이 아니라 기기에 붙는다. 안 지우면 같은 기기에서 다른 계정으로 로그인했을 때 **이전 사용자의 알림이 새 사용자에게 뜬다.** `signOut()` 뒤엔 uid가 없어 어느 문서를 지울지 모른다. (토큰 위치는 v9에서 비공개 문서로 바뀌었지만 원리는 같다)

#### 4. 알림을 탭했는데 참여 화면이 뜸
알림이 초대 링크 URL을 그대로 재사용하고 있었다. 같은 URL이어도 들어온 맥락이 다르다 — 카톡 초대는 "들어올래?"(참여 화면), 리마인더는 "네 그룹에 기록 남겨"(그룹 상세).
알림 전용 Intent를 만들려다 **참여 화면에서 멤버십을 보고 리다이렉트**하는 쪽으로 바꿨다. 초대 링크를 이미 멤버가 눌렀을 때도 똑같이 이상했기 때문에 **한쪽을 고치면 두 입구가 같이 해결**된다. 멤버 조회가 실패하면 막지 않고 기존 흐름으로 보낸다 — 중복 가입은 UseCase가 이미 막는다.

### 🧩 위젯

#### 5. 위젯이 갱신되지 않던 버그 — 틀린 가설 두 번
- **증상**: 이미지가 있는 기록을 지우면 위젯이 갱신되지 않음
- **헛다리**: "이미지 삭제를 기다리느라 늦는다"는 가설을 두 번 세웠지만 둘 다 틀림
- **원인**: 로그를 심자 갱신이 15ms에 끝나고 조회는 첫 갱신 때만 찍힘. 데이터를 `provideContent` **밖**에서 읽어, `updateAll()`이 재구성만 하고 같은 값으로 다시 그리고 있었음
- **해결**: 데이터를 위젯 **상태(state)**에 넣는 Glance 정석 구조로 변경. 부수 효과로 갱신당 조회가 3회 → 1회
- **교훈**: 가설이 반복해서 빗나가면 조건을 좁힐 게 아니라 전제를 의심해야 한다. 오래 끈 진짜 이유는 **조용히 실패하는 구조** — 예외는 삼켜지고 `updateAll()`은 성공을 반환했다 (→ 10번)

#### 6. 위젯이 자기 크기를 모르고 있었다
`LocalSize`로 그렸더니 실제 칸보다 작게 렌더링됨. 기본 `SizeMode.Single`에선 실제 크기가 아니라 **XML에 선언한 최소 크기**를 보고한다 → `SizeMode.Exact`로 변경.
**교훈**: 값이 이상하면 그 API가 **무엇을 알려주기로 약속했는지**부터 확인한다.

#### 7. 위젯만 파랗게 나옴
`GlanceTheme`를 인자 없이 쓰면 **Material You 동적 색상**이 적용돼 배경화면 색을 따라간다 → `ColorProviders`로 앱 색 스킴을 직접 주입.

### 🎨 디자인

#### 8. 주황만 넣었는데 화면이 베이지로 물들었다
`lightColorScheme(primary = 주황)`처럼 일부만 지정하면 **나머지 슬롯엔 M3 기본(보라 계열) 팔레트가 그대로 남는다.** primary를 따라가는 건 `surfaceTint` 하나뿐인데, 이 값이 **높이(tonal elevation)가 있는 표면에 덧칠**되어 카드·앱바가 베이지로 떴다. 남아 있던 보라 계열과 섞이면서 다크 모드 주황은 분홍으로 보였다 → 라이트/다크 색 스킴을 직접 정의.
타이포 슬롯을 비우면 시스템 폰트로 폴백돼 한 화면에서 글꼴이 섞임 → 15개 전부 채움.

#### 9. 입력 칸을 두 종류로 나눔 (일관성 vs 관례)
로그인은 관례대로 외곽선 입력(`AuthTextField`), 앱 내부 폼은 채움형(`FormField`). **일관성은 목적이 아니라 수단**이고, 의도된 분리임을 KDoc에 규칙으로 명시.
포커스 표시를 직접 구현할 때 `interactionSource`를 만들어놓고 **TextField에 넘기지 않으면** 포커스 상태가 영원히 `false`다. 상태를 관찰하는 객체와 발생시키는 객체가 같아야 한다.

### 🧵 코루틴

#### 10. `runCatching`이 코루틴 취소를 삼킨다
`runCatching`은 `Throwable`을 전부 잡아 `CancellationException`까지 "실패"로 처리한다. 화면을 벗어나 취소돼도 조용히 넘어가 구조적 동시성이 깨진다 → `try/catch`로 바꾸고 취소는 다시 던짐.
같은 맥락에서 `ImageCleaner` · `WidgetUpdater`는 **호출자의 스코프에서 떼어냈다.** Storage 뒷정리와 위젯 갱신은 지켜야 할 불변식이 아닌데, 호출자 스코프에서 `await`하면 사용자가 토스트·화면 전환을 기다리고 그 사이 화면이 바뀌면 작업 자체가 취소된다.

## 트러블슈팅 · 설계 판단

### 🔒 보안

#### 1. 보안 규칙은 필터가 아니다
- **문제**: 기록 읽기를 그룹 멤버로 좁히자 `userId ==` 조건만 있는 쿼리(닉네임 일괄 변경)가 **통째로 거부**될 상황
- **원인**: Firestore는 실제 문서가 아니라 **쿼리가 반환할 수 있는 결과 전체**로 규칙을 평가
- **해결**: `isRecordOwner() || isMemberOfRecordGroup()` — 본인 검사를 앞에 둬서 내 기록 쿼리는 `get()` 없이 통과
- **덤**: "사진 한 장당 읽기 +1"로 보고 보류했던 비용은 실제로 **쿼리당 +1**이었다

#### 2. 규칙은 문서 단위로만 막는다
- **문제**: 닉네임 표시용으로 공개된 `users` 문서에 토큰 · 이메일이 같이 있어 **쿼리 한 번으로 전체 이메일 수집 가능**
- **해결**: 토큰은 본인만 읽는 하위 문서(`users/{uid}/private/fcm`)로, 이메일은 읽는 곳이 없어 **저장 자체를 중단**
- **함께 개선**: 알림 Function이 전체 사용자 대신 **대상자 토큰만** 조회, 죽은 토큰은 `lastUpdateTime` 전제조건으로 삭제해 발송 중 새로 등록된 토큰을 지우던 버그 차단

#### 3. Storage는 경로에 소유자를 넣어야 규칙이 소유권을 안다
- **문제**: 기존 경로엔 올린 사람 정보가 없어 남의 사진 삭제 · **덮어써 바꿔치기** 가능
- **해결**: `records/{groupId}/{uid}/…` · `profiles/{uid}/…` · `groups/{groupId}/…`, 덮어쓰기 금지, 그룹 멤버 확인은 Storage 규칙의 `firestore.get()`
- **판단**: 읽기 규칙은 좁히지 않음 — 앱이 쓰는 토큰 URL은 Storage 규칙을 거치지 않으므로, 실제 보호는 URL이 담긴 Firestore 문서(1번)에서 한다

#### 4. 앱 정리 + 서버 안전망
- **문제**: 탈퇴 정리가 중간에 끊기면 데이터가 남고, **Auth 계정이 지워진 뒤엔 규칙상 다시 정리할 방법이 없다**
- **해결**: Auth 삭제 트리거 · 그룹 삭제 트리거 Function이 남은 기록 · 리액션 · 멤버십 · 파일을 정리. 앱 정리는 즉시 반영용으로 유지하고 Function은 **멱등**하게 작성

#### 5. 나가기 순서가 두 군데에 적혀 있었다
- **문제**: 그룹 나가기에 리액션 삭제를 추가했는데 탈퇴 흐름엔 반영되지 않음 — 탈퇴가 나가기 UseCase가 아니라 Repository를 직접 호출하고 있었음
- **해결**: 탈퇴가 나가기 UseCase를 재사용하도록 바꿔 **순서를 한 곳에서만 정의**
- **제약**: 리액션 삭제 규칙이 멤버를 확인하므로 순서는 **리액션 → 기록 → 나가기** 고정. `reactions.{uid}`는 사람마다 경로가 달라 복합 인덱스를 만들 수 없어 앱에서 필터링

#### 6. App Check "잘못된 요청" 52%
- **문제**: enforce 직전 지표에서 요청 절반이 검증 실패
- **원인**: **Play Integrity가 콘솔에 미등록**(SDK만 있었음) + 개발 기기 변경 후 **디버그 토큰 미등록**. 사용자가 거의 없어 그동안 드러나지 않음
- **해결**: 둘 다 등록 후 Play · 디버그 빌드 모두 100% 확인을 보고 enforce
- **교훈**: "SDK를 넣었다"와 "검증되고 있다"는 다르다

#### 7. 구버전 호환을 버린 판단
규칙 변경은 모든 버전에 즉시 적용되므로 원래는 전환 기간 코드가 필요하다. 실사용자 0명이라 **전환 코드 없이 바로 새 구조로** 바꾸고, 출시 직전 데이터를 전부 정리해 모든 데이터가 새 구조로만 존재하게 했다. 전환 코드는 나중에 지워야 할 부채이기도 하다.

### 🏗 빌드

#### 8. R8 — 이름에 기대는 곳 찾기
`toObject()` 사용처 0건(매퍼로 직접 파싱)을 확인하고, **DataStore에 `enum.name`으로 저장하는 설정**과 **Credential Manager**(빠지면 릴리스에서만 구글 로그인 실패)에 keep 규칙 추가. **AAB 21.5MB → 7.34MB.**

#### 9. 로컬 릴리스 빌드만 로그인이 막힘
API 키를 SHA-1로 제한해뒀는데 허용 목록엔 디버그 키와 **Play 앱 서명 키**만 있었다. 업로드 키로 서명한 APK는 원래 Play가 다시 서명하므로 그대로 실행될 일이 없었던 것 → 업로드 키 SHA-1 추가.

### 🖼 사진 추출

#### 10. 미리보기가 작아지자 저장 해상도도 떨어짐
옵션 UI가 늘며 미리보기가 작아졌는데, 미리보기 크기 그대로 캡처하고 있었다 → 캔버스는 항상 **360dp 고정**으로 그리고 미리보기만 `graphicsLayer`로 축소.

#### 11. 저장 버튼이 영원히 로딩 중
- 순서를 바꾸면 이미지 로딩 카운터가 0으로 초기화되는데, 이미지는 `key(slot)`로 이동만 해서 **다시 로드되지 않음** → 카운터 키를 순서와 무관한 Set으로
- 타이포는 사진이 없는데 대기 조건에 포함 → 대기 대상에서 제외

#### 12. 색은 템플릿별로, 카드만 예외 매핑
색을 하나로 공유하면 타이포에서 주황을 고른 뒤 스트립도 주황이 된다 → 템플릿별 저장, 고른 적 없으면 대표 색. 카드는 흰 액자 위라 흰 배경 → 베이지, 검정 → 차콜로 바꿔 그림. 사진 위 글씨 · 카드 캡션은 가독성 때문에 색 옵션에서 제외.
